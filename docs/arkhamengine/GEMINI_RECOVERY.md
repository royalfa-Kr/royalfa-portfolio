# Mythos Weaver — Recuperación de trabajo con Gemini

## Objetivo

Conservar el proyecto aunque una conversación deje de responder.
Este procedimiento no garantiza corregir un problema del servicio.

## Antes de cualquier problema

- Guardar cambios útiles en el repositorio.
- Mantener STATE y HANDOFF actualizados.
- Hacer commits pequeños.
- No depender del chat como único almacenamiento.

## Si aparecen respuestas genéricas repetidas

1. Guardar mensajes útiles antes de cerrar o actualizar.
2. No reenviar repetidamente todos los adjuntos.
3. Probar una pregunta sencilla en un chat nuevo, sin archivos.
4. Si falla, probar otro navegador y otro modelo, cuando estén disponibles.
5. Registrar fecha, modelo, navegador, mensaje y resultado.
6. Reportar el problema mediante la opción de comentarios del producto,
   revisando que no se adjunten secretos.
7. No borrar actividad o conversaciones como primer paso.
8. No convertir documentación a Python como solución automática.

No atribuir la causa a un formato, documento o bloqueo sin evidencia.

## Cuando vuelva a responder

1. Compartir HANDOFF.md.
2. Compartir STATE.md y la tarea activa.
3. Pedir que enumere lo recibido y lo que falta.
4. Enviar solo los archivos necesarios para esa tarea.
5. No intentar reconstruir todo el historial.

## Mensaje inicial

Vamos a continuar Mythos Weaver desde el repositorio.

Primero lee el HANDOFF que compartiré.
No implementes todavía.

Confirma:
- Estado actual.
- Próxima tarea.
- Archivos necesarios.

No supongas acceso a mi disco ni ejecución de comandos.
La documentación objetivo no equivale a código implementado.
